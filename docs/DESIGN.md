# Local agent bridge

Approved design: a TypeScript CLI, invoked by Claude Code or Codex, backed by SQLite. No daemon, HTTP listener, persistent polling loop, or automatic message injection into interactive sessions. Runs use installed authenticated CLIs. Node 24.10+ runs erasable TypeScript directly; node:sqlite avoids runtime dependencies. macOS/Linux first.

State lives at AGENT_BRIDGE_HOME or ~/.local/share/agent-bridge, never inside a source repository by default. Store workflows, sessions, tasks, events, and explicitly acknowledged inbox messages. Prompt/output/log files are private local artifacts, never committed. Use WAL, foreign keys, busy timeout, and transactions for claims and completion delivery.

Workflow membership is explicit and repository-scoped; branch/PR metadata is informative. A task has a requesting session, a worker session, a workflow, a prompt, a model, repository and commit metadata, timestamps, status, artifact paths, and a parent task for follow-ups. Interactive sessions are only last-seen; a native ID alone does not authorize resuming an interactive session. Only bridge-managed sessions can be resumed by follow-up.

Submit waits by default; --background creates a detached worker which exits at completion. Each task has a finite timeout (default 20 minutes). Workers heartbeat every 5 seconds with a 30-second lease. Claims atomically prevent simultaneous bridge turns in one session. Expired tasks become interrupted on reconciliation, once only; never automatically retry or reclaim a possibly still-running provider. A late worker must not overwrite interruption or send success. No PID-based killing of arbitrary stale processes. Inbox reads never acknowledge; explicit ack is recipient-scoped and repeatable. Completion/error and inbox delivery commit atomically once.

Providers spawn argv without a shell; prompts go through stdin. Codex: global --no-daemon on both initial and resume invocations, exec --json with explicit model, read-only sandbox, no interactive approvals; resume native thread for follow-up using supported global flags. Claude: -p with stream-json, verbose, explicit model if supplied, noninteractive permission handling with read-only tools, and --resume for follow-up. Preserve normal authenticated configurations; never bypass approvals or copy credentials. Denied tools fail/report through the provider. Capture documented native IDs and final messages; nonzero exit, provider error event, malformed/no final result, spawn failure, signal or timeout are failures, never empty success. Store raw event logs separately from concise task results. No silent model fallback. Transport layer returns provider text; review JSON can be requested by prompt without claiming a universal schema.

CLI commands: session register, session list, context, submit, follow-up, status, result, list, send, inbox, ack, doctor; internal worker command. JSON stdout for agent consumers, human-readable help/errors. session register requires provider/repo/workflow and optional role/native-id. submit requires provider/repo/prompt or prompt-file and either requesting session (--from) or workflow; worker inherits workflow from requester. Validate repo/workflow consistency. follow-up takes prior task and new prompt, resumes only its managed worker session. result fails nonzero until success and reports state. No automatic GitHub posting, merges, editing, global installation, or checkout mutation. Snapshot HEAD metadata and report when current HEAD differs; first version reviews caller-prepared checkout and does not claim isolated PR snapshots.

First version supports general textual research/review tasks. Documents/images depend on configured harness tools; no promise of app-tool parity. No arbitrary session discovery or unsolicited wake-ups. A portable agent skill explains registration and checkpoint polling; users invoke it by path or install it explicitly.

Verification: typecheck, real SQLite tests across reopen and simulated consecutive days/gaps, races/claims, fenced late completions, inbox ack/delivery, subprocess fake providers for success/error/resume/background/timeout, and a bounded live provider smoke test if authentication permits. Any live test limitation is recorded honestly.
